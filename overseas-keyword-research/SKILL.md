# TikTok 关键词 / 标题 / 标签（出海内容用）

目标：吃透这个产品，挖到海外用户真实在用的词，最后落到三样东西——能直接贴的视频标题、能挂的话题标签、能查能用的关键词库。
老板要求：关键词越多越好，不设上限，不要提前筛词；标签要真、要多（50~80 个）、要能看出哪个流量大；标题要够用（10~15 条），不要商品标题。

默认"TK 标题"指**视频标题（caption，发视频时贴的那句）**，不是 TikTok Shop 商品标题；用户明确说要做上架标题时，才额外给商品标题。视频标题和 hashtag 是两件事：标题进 caption 第一行，hashtag 单独一页，发视频时给人挑着加。

## 执行方式（先看这条，优先级最高）
- **不要向用户确认任何问题**。用户已明确要求：这类任务不要麻烦他，直接把成果给他看。不问他品名、不问是商品标题还是视频文案、不问要不要嵌图、不问做哪个站点。
- 信息不足就用合理默认，并在交付里一句话标注：品名从主图读，读不出标"品名待用户确认"；默认做视频标题 + 标签；站点默认美国（美区）；没收到图就按规定留空位。默认项不反问。
- **一次做完再交付**：看懂产品→定种子词→扩词→证据挖掘→分层→标题→标签（含真实数据核验）→卖点→出一份 xlsx。中途不汇报进度、不请示、不征求确认。
- 只有两种极端情况才开口：用户既没给产品图、文字也看不出是什么产品；所有扩词和证据来源都不通。即使开口，也要先把能做的部分做成文件交付。

## 步骤

### 1. 看懂产品
从产品图和用户给的词判断：是什么、卖给谁、解决什么问题、有哪些可见卖点。信息不够也不问，按默认判断，在交付里标注不确定项。
- **主动记录产品名称**：用户发来的品名（品牌 + 品类 + 规格/颜色）单独记下；用户没给名称时，从主图包装/文案里读，读不出就标"品名待用户确认"，不要自编品牌名。
- **主图必须进交付表**：用户发来的产品主图要嵌入交付文件（见"产品概览"），让看表的人一眼知道产品长什么样、叫什么。图片在本地桌面等非允许目录时，先复制到工作目录再嵌入。
- **顺手把材质/软硬/容器/效果拆一遍**：这产品是什么料（硅胶/不锈钢/玻璃/塑料/金属）、硬的还是软的、能不能折叠、是不是容器、解决什么问题。拆出来直接对应第 8 步的「材质属性」标签组，不单独建"产品分类"页。
- **材质看不出来就写"材质待确认"，绝对不许猜**。看图经常分不清硅胶和塑料、不锈钢和铝、尼龙和涤纶；描述里出现 "silicone" 这种字样才算确认，光凭颜色、光泽、哑光质感去推断不算。
  - 没确认的材质：产品概览里标 `材质待确认（需实物质检/供应商确认）`；标题里不写具体材质词；材质属性标签组里对应的标签（`#silicone` `#stainlesssteel` `#glass` 等）不挂。
  - 宁可少挂一个标签，也不能把一个塑料件写成硅胶——这属于对产品的虚假描述，发布后没人会去核对，出事就是售后和差评。
  - 交付时点名：哪几项材质没确认、建议向谁确认（供应商/质检报告）。

### 2. 定种子词（5~15 个，英文）
用户给中文就先翻成海外真实说法。覆盖：品类大词、同义说法（如 food storage container / lunch box / meal prep container / bento box）、品类+核心属性、品类+使用场景。

### 3. 暴力扩词（有 shell 且能联网时）
先探测，几秒就知道哪些来源能用：
```
python3 scripts/expand_keywords.py --seeds "词1" --probe-only
```
全都不通就别往下跑了，直接走"网络不通"的做法。有能用的再扩词：
```
python3 scripts/expand_keywords.py --seeds "词1" "词2" --level normal --out ./kw
```
- 只用标准库，不用装东西；`--dry-run` 先估请求数
- **第一次先用 normal，确认能出词再换 `--level full`**（词最多，老板要量就用 full，但请求数是 normal 的 3 倍多）
- 脚本自带总时间上限（默认 5 分钟，`--max-minutes` 可调），到点会输出已抓到的部分，不会一直卡着
- **不要把输出接到 `| tail`**：那样跑完前什么都看不到，像卡死。直接运行，进度会实时打在终端；跑得久就放后台并把日志写到文件
- 不通的来源开跑前就被剔除；运行中连续失败的也会自动停用（"抓不到换一个"），报告里写明
- 来源 amazon / google / youtube / bing，`--market` 可选 us/uk/de/ca
- 输出：keywords.csv（全部词，带粗标签、热度代理、来源）、title_words.csv（贴题词里的高频单词排行，写标题时按它挑词）、keywords.json（同上加运行报告）

**网络不通时**（比如 claude.ai 对话里 bash 联网是关的）：不要假装跑过，也不要把活推回给用户。跳过扩词，直接用第 4 步的搜索和网页读取挖词，交付里注明扩词来源受限、哪几个源没抓到。

### 4. 证据挖掘（用搜索和网页读取，补脚本抓不到的，尤其是 TikTok）
- TikTok：爆款同类商品的标题、话题标签、视频文案和评论。**同类爆款的标题是最直接的参考，优先看**
- 亚马逊：热销品标题、五点、评论原文，重点看 1~3 星差评
- Reddit / YouTube 评论 / Pinterest：用户怎么吐槽、怎么夸
- 抓不到就换下一个；全抓不到，让用户贴数据（格式见 references/import-formats.md），用 `--merge` 并进词库

### 5. 整理关键词库（合并成一张表）
全部词只放一张 `关键词库` sheet，三列：层级 / 英文关键词 / 中文释义，统一排版（蓝底白字表头、细边框、自动换行）。
- 先挑"能进标题"的词分四层排在前面，每个英文词配一行中文释义：
  1. **核心词**：品类词，放标题最前面（搜索权重最高的位置）
  2. **属性词**：材质、尺寸、数量、功能（如 glass, 24 pack, leakproof），参考 title_words.csv 的高频词
  3. **人群/场景词**：for work, for kids, meal prep 等
  4. **卖点词**：来自用户原话里的痛点正面表达（如 no leaks, stain resistant）
- **中文释义必须逐条准确**：每个英文词配一句到位的中文，不许留"待核对""待补充""占位""暂无中文"这类兜底文字，也不许把词面直译成读不懂的中文。
- **用户给的东西必须并进表**：用户发的基础关键词、口语卖点、产品图上的英文说明（材质、尺寸、功能句）全部要落进词库和卖点表，不能只在标题里用一下就丢。
- 其余搜索词排在四层之后，层级标"其他搜索词"；**离题词（相邻品类、竞品品牌、IP 联名、无关长尾词）直接删，不进表、不留"离题词"层级、不靠底色区分**。
- **不设来源列、热度代理列、备注列**；标签、排名、来源数、出现模式、词数等分析列一律不进交付表。
- 避开：竞品品牌词、绝对化/夸大用语（best, #1 之类）、与产品不符的词。TikTok Shop 的标题规则和字数限制以后台当前要求为准，拿不准就告诉用户去核对，不要编数字。

### 6. 标题（英中双语，强制；默认做视频标题）
出 **10~15 条视频标题**（caption 第一行那句话）。3 条太少，用户会嫌不够用；15 条左右是他认可的量，也不要堆同一句话的近义词。
- 每种类型各来一两条，别全是一个模子：痛点反转型、后悔型（why didn't I buy this sooner）、POV 第一人称、前后对比型、功能演示型、折叠收纳型、小厨房型、材质卖点型、提问钩子型、合集型、测评型、教程型。
- **凡是标题，一律英中双语成对给出**：英文在上、中文在下；英文是能直接贴进 caption 的成品，中文只作对照。
- **不要 Shop 商品标题**：用户明确说过"我不要商品标题"，那种堆关键字的长标题不要混进来；只在用户明确要上架标题时才单独给。
- 表内列固定：序号 / 视频类型 / 英文标题（可直接发布）/ 中文译名 / 建议标签。
- 不要为了塞词写成读不通的堆砌，读起来要像真人会说的一句话；产品事实（材质、能立几把勺、可折叠、防滑、易清洁）要真的写进标题里，不要空泛。
- 中文译名要对应英文原意，不额外加英文标题里没有的卖点或形容词。

### 7. 卖点
- **卖点**：卖点 ↔ 关键词 ↔ 用户原话（英文 + 中文）；不设来源列、热度代理列。没信息量的原话（Great product）不要放。
- **原话必须是真抓到的**：用户原话只能来自评论、标题、五点描述里实际出现的句子。抓不到就留空、写"未取到原话"，**不许自己造一句听着像老外说的话**——表里没有出处，别人查不出来，这是最难发现的问题。
- **内部留痕（不进交付表，但自己要能核验）**：每个原话和关键卖点词，内部记一条 `词/原话 → 来源URL（或来源文件+行号）`。交付表里不出现来源列，但被问到"这句哪来的"要能立刻指出来；抽查时按这份记录逐条搜一遍就能验。
- **不许凭记忆补**：任何词、任何量、任何原话，没有当下抓到的证据就不写；记不清就去抓，抓不到就空着。
- 内部记录缺口（有卖点没人搜、有人搜没覆盖、未取到的来源及补法），但**不单独建"缺口与未抓到"sheet 交付**；缺口在回复里一句话点名。
- 热度只能作为内部联想排名代理参考（高/中/低/未知），不写进交付表；用户给了导出的搜索量才引用搜索量。
- 词上千时不逐条贴出来，按类别给表格。

### 8. 标签（hashtag，独立一页，数据必须真实）
标签**单独一页**（不跟标题、不跟关键词混），`标签` 页五列：分组 / 标签 / 中文 / 视频数（条）/ 播放量（监测）。同一页内按分组上色区分，组内按播放量从高到低排。

分组固定五组，**不要"产品分类"这一组（已明确否决）**：
1. **泛流量**：`#fyp` `#foryou` `#satisfying` `#amazonfinds` `#tiktokmademebuyit` `#tiktokshop` `#productreview` 等，负责进推荐池
2. **品类大词**：`#kitchengadgets` `#kitchenhacks` `#cookinggadgets` `#homecooking` `#kitchentools` `#kitchenware` 等，本类目最大的池子
3. **收纳颜值**：`#kitchenorganization` `#kitchendecor` `#smallkitchen` `#aesthetickitchen` `#cleantok` `#mealprep` 等，负责好看、好收纳的钩子
4. **材质属性**：按产品材质/软硬/效果逐个对应——硅胶→`#silicone`、不锈钢→`#stainlesssteel`、可折叠→`#foldable`、防滑→`#antislip` `#nonslip`、易清洁→`#easytoclean` `#dishwasher`、它托的那些器具→`#spatula` `#tongs` `#ladle`。**这一组是"这件东西是什么料、什么手感、什么效果"，每个产品都要有**
5. **本品词**：`#spoonrest` `#lidholder` `#utensilholder` 这类精准词，量小、单独放最后，并一句话说明它只起类目定位作用，不要当流量词

**数量要求**：整页 50~80 个，不能给二十几个就交差；每组至少 5 个。用户说"有点少"就是数量不够，继续找，别辩解。

**数据必须真，不许编**：
- 用随包脚本批量查，别一个个手点：
  ```
  python3 scripts/probe_tiktok_tags.py kitchengadgets kitchenhacks silicone --out ./tk_tags_raw.csv
  ```
  5~9 秒一个，40 个约 5 分钟
- **一定放后台跑，给整批设总时长上限（10 分钟），盯日志**。日志里一行行出标签就正常；连续多次报超时/失败，说明被限流或站点抽风，**立刻停掉，不许干等**。
- **跑不完就用手上已有的数据出表**：不因为一批没跑完就卡着不交付；缺的那几个留空，在交付里点名（"这几个抓取失败，数据空着"）。
- 脚本做法：逐个抓 `https://toklytics.app/hashtag/<tag>`（tag 小写、不带 #），正则取 `used in N TikTok videos` 和 `X total views`；单次失败重试 2 次，还失败就**留空**，绝不估数、绝不编数
- 抓到的数写"视频数（条）"和"播放量（监测）"，并在表头/说明里标口径：**第三方监测收录的样本量，不是官方全站总量，只能用来比大小、排先后**；用户问"真的假的"就这么答，不要嘴硬说官方
- 实测同一标签两家平台差异很大（`#kitchenhacks` 2.1B vs 2.8B、`#kitchengadgets` 898.5M vs 3.5B），所以不写"官方数据"四个字
- **交付时要交代缺口**：哪几个标签没抓到数（如 `#fyp` `#foryou`），在回复里点名说清"这几个空着、抓了 3 次超时、没编数"，不要闷着让人自己去发现

**美区专用**：只出美国市场在用的英文标签，不混其他地区、不混中文标签、不混非英语市场的本地写法。`#amazonfinds` `#tiktokmademebuyit` `#tiktokshop` `#cleantok` `#aesthetickitchen` `#apartmentliving` 这类是美国本土长起来的，可以直接用。

**怎么配**：每条视频 5~6 个——2 个泛流量 + 2~3 个品类大词 + 1 个材质属性或本品词。表里不写死"每条必须这几个"，给人自己挑。

## 交付：只出一份文件（强制）
- **命名不带"研究"二字**：文件名和页内标题写 `品牌 + 品类 · TikTok 关键词与标题`（例：`HOMESMART 折叠式厨具架（带锅盖架）· TikTok 关键词`）。"研究""调研""报告"这类词用户嫌难听，一律不用。
- **所有结果合并进同一个交付文件，一份就够，不要拆成多份 csv/xlsx**（不要再分别导出 keywords、title_words、分层词库、卖点映射、离题词等多个文件）。
- 推荐用一个工作簿（.xlsx）多 sheet 组织；用户明确要 csv 时，就一个 csv 内用分区/列段区分。单一文件内部分区如下：
  1. `产品概览`（放在最前）：产品名称（品牌+品类+规格颜色，英中对照）+ 产品一句话描述 + 用户发来的主图（单元格内嵌图，不是浮动图）。没收到图时只留名称与描述，位置留好。
  2. `标题`：序号 / 视频类型 / 英文标题（可直接发布）/ 中文译名 / 建议标签 —— 只放能直接贴进 caption 的视频标题，**不要塞 TikTok Shop 商品标题**；用户要上架标题时另开一页或另给，不混在同一页
  3. `关键词库`：层级 / 英文关键词 / 中文释义（四层词在前，其余搜索词在后；不写来源、热度、备注等分析列）
  4. `卖点`：卖点 / 对应关键词 / 用户原话（英文）/ 用户原话（中文）（不写来源、热度列）
  5. `标签`：分组 / 标签 / 中文 / 视频数（条）/ 播放量（监测）—— 五组（泛流量、品类大词、收纳颜值、材质属性、本品词），组内按播放量倒序；每页 50~80 个
- **`标题` 和 `标签` 是两页，不能合并**：标题是 caption 那句话，标签是挂在后面的 hashtag；合成一页会让人分不清哪个是哪个。
- **不单独建"缺口与未抓到"sheet**；缺口只在内部记录或口头简述。
- 脚本跑出的中间 csv（keywords.csv、title_words.csv、keywords.json、tk_tags_raw.csv 等）属于工作中间产物，留在工作目录即可，不作为交付物发给用户。

### 9. 产品概览（嵌图 + 名称，强制，每次必出）
- **每一轮交付都必须带 `产品概览` sheet，放在第一个位置，不能省**：左上角写品名，下面嵌主图。图片随记录走，排序/筛选时跟行不飘（用单元格内嵌图，不用浮动图）。
- 概览页固定三行文字 + 一张图：
  1. 产品名称（品牌+品类+规格颜色，中文）
  2. 英文品名（标题参考用）
  3. 产品描述（一句话：材质/数量/配件/适配场景）
  4. 主图嵌在文字下方的合并单元格（跨名称列与描述列合并），行高按图高留足，不留"双击图片"之类的空位占位。
- 品名优先用用户发的名称；没有就从主图包装文案读取；读不出标"品名待用户确认"，不自编品牌名。
- 嵌图命令：在线表用 `+cells-set-image --range <单格> --image <工作目录内图片>`，再 `+cells-merge` 把图格横向合并、`+rows-resize` 留足行高；本地 xlsx 用 openpyxl 的 `ws.add_image()` 锚到概览页合并单元格。
- 图片路径在桌面等允许目录之外时，先复制到工作目录（`_中间产物/` 或项目目录）再嵌入，不要直接引用桌面绝对路径。
- 用户没发图时，概览页位置和三行文字照常写好，图格留空并标注"未提供主图"，不要整张概览页省略。

## 输出（中文）
1. 产品理解（一小段，含材质/软硬/是否容器/效果；材质没确认的标明"待确认"）
2. 视频标题（10~15 条，英中双语，可直接发布）
3. 关键词库（四层词 + 其余搜索词，逐条中英对照，同一份交付文件内）
4. 卖点/原话对应（原话必须真实取到）
5. 标签（五组，带真实监测数据；组合怎么配一句话说明；没抓到的点名交代）
6. 待确认/没抓到清单（材质待确认项、空数据的标签、没取到原话的卖点），一两句话说完，别写一大段

## 底线
- 不确定写"不确定"
- **材质猜不得**：看不出来就写"材质待确认"，标题不写材质词、材质标签不挂；宁缺不编
- **没证据的就不写**：词、播放量、用户原话都必须当下抓到，抓不到留空；禁止拿记忆填空，内部记好来源以便被抽查
- **抓取别干等**：后台跑 + 总时长上限，连超就停，用已有数据出表并交代缺哪几个
- **中文释义不许留"待核对/占位/暂无"**，每条都要翻到位
- **文件名和页内标题不带"研究"**，用 `品牌 + 品类 · TikTok 关键词与标题`
- **离题词直接删**：相邻品类、竞品品牌、IP 联名、无关长尾词一律不进词库，不留"离题词"分层、不靠底色区分
- 可以出标题草稿；不做视频脚本和消费心理策略
- **标题必须英中双语成对；交付文件只出一份，不拆多份；词库只一张表；交付表内不出现来源、热度代理、备注等溯源列**
- **标签数据不许编**：只能来自真实抓取，抓不到就留空；没抓到就不能写数字，也不能用"大概、约"糊过去
- **只做美区**：标签只用美国市场在用的英文标签，别混其他地区
- 交付即结束，不再追问"要不要改标题""要不要多加点词"；用户主动提修改再改
